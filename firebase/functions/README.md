# firebase/functions

Cloud Functions 2nd gen, TypeScript (strict), Node 22, ESM. One function per use case (D28). The contract is
[`API.md`](API.md); the machine-readable form is `contracts/schemas.json` (generated by `npm run gen:schemas` from the zod
schemas the server validates with, and checked for staleness by a test).

## Layout

```
src/
  index.ts          exports every function by name (callables, getIcs, appStoreNotifications, triggers, jobs)
  app/              Deps (everything outside the process, injected), UseCase, registry, createDeps (the real wiring)
  contracts/        zod request and response schemas, shared primitives, generated schemas
  public/ token/ owner/   one use case per file; `access` says who may call it
  lib/              pure rules (rules.ts, freeSlots.ts, time.ts), calendar (the booking transaction), registrations (D42),
                    deletion cascades, contacts, ics, log (scrubbing logger), rate limiting, sanitize, store helpers
  messaging/        ClientMessenger, EmailProvider (Resend adapter, disabled and emulator stand-ins), WhatsApp (+ Cloud API provider, disabled)
                    and the email texts in 14 localizations
  push/             PushSender (+ FCM and emulator senders), the FCM payload builder
  auth/ billing/    PhoneVerifier (Firebase Auth phone provider), AppStoreVerifier (Apple adapter; Unconfigured until the certs of H14 exist)
  http/             invokeUseCase (the transport-independent gate), callable wrapper, getIcs and Apple webhook handlers
  triggers/ jobs/   onBookingWritten / onInboxItemCreated handlers, cleanupJob steps, sendReminders
test/
  unit/             pure code, no emulator (715 tests, ~4 s)
  rules/            firestore.rules, storage.rules and the deny-all production rules (@firebase/rules-unit-testing)
  integration/      every use case against the Firestore, Auth and Storage emulators, with a fixed clock and fakes
  transport/        the deployed entry points through the Functions emulator (callable protocol)
  fixtures/         rules.fixture.json, generated from the iOS Swift rule types (../scripts/rules-fixtures/generate.sh)
```

## Ideas worth knowing before you change anything

- **Double booking (D32).** Everything that *occupies* time (`createBooking`, `holdSlot`, direct reschedule, accepting a
  reschedule request, registering a client) reads and bumps one document, `calendarLocks/{ownerUid}`, inside its
  transaction. Two such transactions for one professional conflict and the loser retries against the winner's booking.
  This does not depend on how a database treats an insert into a queried range. Tests race 2 and 10 callers.
- **The registration counter (D42)** lives in `accounts/{uid}.registrations.count`, is only incremented, and a client is
  counted once (by client id or by phone). A confirmed booking from a new phone registers it immediately; the app's later
  `reserveRegistration` for the same phone does not count again. Deleting a client never touches the counter or the ledger.
- **Tokens** (manage links, portal links) are 128-bit; only SHA-256 is stored. `findBookings` and reminders mint *additional*
  tokens because a hashed token cannot be shown again (at most five stay valid per booking).
- **The mirror of the iOS rules.** `lib/freeSlots.ts`, `lib/rules.ts` read the same cases as the Swift code through
  `test/fixtures/rules.fixture.json`, produced by compiling the real Swift types. Regenerate with
  `firebase/scripts/rules-fixtures/generate.sh` when a Swift rule file changes and commit the JSON.
- **Logging.** `lib/log.ts` accepts a closed list of field names with id-shaped, label-shaped or numeric values. Free text has
  no field. Never add `console.*` (lint forbids it) or log an error message (SDK errors can quote documents).
- **No `any`** without a comment; **zero lint warnings** (`npm run lint`).

## Adding a function

1. Schemas in `src/contracts/{public,owner}.ts`; 2. a file in `src/{public,token,owner}/` with `defineUseCase`;
3. add it to `src/app/registry.ts` and `src/index.ts`; 4. document it in `API.md` (section 5 or 6 and the index in section 11);
5. `npm run gen:schemas`; 6. tests (integration for behavior, unit for pure parts). `test/unit/contracts.test.ts` fails if
any of those steps is missing.

## Commands

`npm run lint | typecheck | build | test:unit | test:rules | test:integration | test:transport | gen:schemas | seed | emulators`.
The emulator suites need to be started through `scripts/test-firebase.sh` (or `firebase emulators:exec`) from the repo root.
