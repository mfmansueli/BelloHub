## Known risks (watch and report)

1. **SwiftData + CloudKit** is hard to debug and has model restrictions (`05-DATA-MODEL.md` §1). Stage S2 contains a spike and a written go/no-go. The fallback is Core Data with `NSPersistentCloudKitContainer` behind the same repository protocol.
2. **Two identities:** phone number on the server, Apple ID for the record. Warn in onboarding and `Privacy`; offer export.
3. **Photos fill the free 5 GB of iCloud.** Compression, space warning, `iCloud full` state.
4. **The CloudKit schema only grows in production.** Review every model change; deploy the schema to Production before each release that changes it.
5. **Devices without Apple Intelligence** (or unsupported locale): the manual record (`Tx-Form`) must be first class.
6. **Web E2EE trust problem:** the server serves the page that encrypts, so a compromised server could serve bad code. Mitigations are in `06-PRIVACY-SECURITY.md` §6; do not claim more than that in copy.
7. **In-app browsers** (WhatsApp, Instagram) have quirks; the web test matrix is in `10-WEB-BOOKING.md` §8.
8. **Notification text without client names** (lock screen).
9. **Unreviewed languages and legal texts.** There are no reviewers yet. Public release is per market (D36); TestFlight internal until then. `check-strings.sh` prints reviewed coverage; `legal/STATUS.md` shows what is draft.
10. **Verification SMS** can be slow or filtered in India, Indonesia, Turkey, Saudi Arabia and the UAE (D37, `16-MARKETS.md` §3).
11. **Health-data residency** in the UAE and Saudi Arabia: wave 4 only after a written legal opinion (`16-MARKETS.md` §1).
12. **Individual developer account:** the App Store shows the owner's personal name as seller; in the EU a seller of subscriptions must declare trader status and publish contact details (H16). An organization account can be created later and the app transferred.
