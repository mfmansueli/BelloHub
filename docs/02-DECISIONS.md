# 02 · Decisions

When this file disagrees with the prototype or with another document, **this file wins** (except `CLAUDE.md` at the repo root, which wins on code architecture and process). Cite decisions by number in commits, tests and reports.

## Decided

| # | Decision | Why |
|---|---|---|
| D1 | **iPhone only**, SwiftUI, iOS 26+ (Liquid Glass). `TARGETED_DEVICE_FAMILY = 1`. Clients use a web page on any device. No iPad, Mac, Android or professional web app in v1. *(Changes the earlier "iPhone and iPad" plan.)* | The professional works from her phone. One form factor halves design and test cost. |
| D2 | **The client record and photos live on the iPhone and in the professional's private iCloud** (SwiftData + CloudKit private database). Never on our servers. | Health data private by construction, works offline, no record server to defend. |
| D3 | **Firebase is the backend for the client-facing side only** (Firestore, Cloud Functions, Auth for phone verification, FCM, App Check, Hosting, Cloud Storage for large sealed payloads). It stays **behind `BookingRepository`** (protocol) so it can be swapped. *(Mateus's expertise; a managed-Postgres alternative such as Supabase was considered and not adopted.)* | The server holds little and no clinical content, so the backend's own features matter less than speed and team skill. |
| D4 | **No financial operations.** Service price is optional information. | Product rule. |
| D5 | **Team is out of v1.** The screen stays and says "later". | Multi-professional needs key sharing and shared records; hardest part with iCloud. |
| D6 | **No decorative theme.** | Product rule. |

| D11 | **Cancellation and reschedule rules are the professional's** (`CancelPolicy`). The client reads them before booking, in the confirmation, in the reminder and on her management page. | Same outcome for most cases without client accounts. |

| D16 | **Service contraindications warn, never block.** Patch test is a per-service setting. | The clinical decision is hers. |

Adapt the copy of screen `7.8` (Delivery: "Save to Files or share"; remove the email and 7-day text; keep "Your clients' data stays private to you") and list it under "Design additions". | LGPD/GDPR portability without breaking D2. |
| D19 | **Add-ons and guests add time**; the booking occupies the total time in sequence. Price is shown, never charged. | Combos and pairs without payments. |
| D20 | **One motion layer**: staggered arrival, press response, sheets, switch, success, one ambient hero. Everything respects Reduce Motion. `09-MOTION.md`. | Polish at zero per-screen cost. |
| D21 | **Sealed mailbox (end-to-end, client → professional).** Anything sensitive a client sends (health form, consent signature, skin check-in photo) is encrypted **in her browser** with the professional's public key (HPKE) and stored as an opaque envelope. The iPhone downloads, decrypts, stores in the vault, and the server deletes it. Resolves open item O4. | Server can never read it. |
| D22 | **Recovery key**: 12 words (BIP-39 English list, 128-bit entropy), generated on the iPhone, shown once with Face ID, never sent to Bello. The inbox key pair **and** the vault key are derived from it. Also in iCloud Keychain. | Lose the phone, keep the record. |
| D23 | **AI runs on the device**: SpeechAnalyzer for transcription, Foundation Models for structuring. If unavailable or the locale is unsupported, fall back to manual form and dictation. **"Cloud help" does not exist in v1**: the row in `AISettings` (7.5) is shown **disabled** with the label "Not available yet" (list under "Design additions"); only a disabled feature flag and a marked interface exist, off by default, and any future use would ask the professional first. Tests generate expected values from Foundation plus a short list of hand-verified quirks; nothing is asserted from memory. | Correctness across markets. |

## Known risks (watch and report)

1. **SwiftData + CloudKit** is hard to debug and has model restrictions (`05-DATA-MODEL.md` §1). Stage S2 contains a spike and a written go/no-go. The fallback is Core Data with `NSPersistentCloudKitContainer` behind the same repository protocol.
2. **Two identities:** phone number on the server, Apple ID for the record. Warn in onboarding and `Privacy`; offer export.
3. **Photos fill the free 5 GB of iCloud.** Compression, space warning, `iCloud full` state.
4. **The CloudKit schema only grows in production.** Review every model change; deploy the schema to Production before each release that changes it.
5. **Devices without Apple Intelligence** (or unsupported locale): the manual record (`Tx-Form`) must be first class.
6. **Web E2EE trust problem:** the server serves the page that encrypts, so a compromised server could serve bad code. Mitigations are in `06-PRIVACY-SECURITY.md` §6; do not claim more than that in copy.
7. **In-app browsers** (WhatsApp, Instagram) have quirks; the web test matrix is in `10-WEB-BOOKING.md` §8.
8. **Notification text without client names** (lock screen).
9. **Unreviewed languages and legal texts.** There are no reviewers yet. Public release is per market (D36); TestFlight internal until then. `check-strings.sh` prints reviewed coverage; `legal/STATUS.md` shows what is draft.
10. **Verification SMS** can be slow or filtered in India, Indonesia, Turkey, Saudi Arabia and the UAE (D37, `16-MARKETS.md` §3).
11. **Health-data residency** in the UAE and Saudi Arabia: wave 4 only after a written legal opinion (`16-MARKETS.md` §1).
12. **Individual developer account:** the App Store shows the owner's personal name as seller; in the EU a seller of subscriptions must declare trader status and publish contact details (H16). An organization account can be created later and the app transferred.
